# P1-3: Implement sandbox lifecycle (create, launch, teardown)

**Status:** open
**Depends on:** P1-1

## What to do

1. Implement `Runtime.CreateContainer` in `internal/matchlock/runtime.go`:
   - Instantiate an `sdk.Client`.
   - Configure a `SandboxBuilder` via `sdk.New(image)` with the working
     directory, environment variables, and any other options from
     `CreateContainerOptions`.
   - Return a `Container` struct holding the client and builder (do NOT call
     `Launch` yet — that happens in `Start`).

2. Implement `Container.Start` in `internal/matchlock/container.go`:
   - Call `client.Launch(builder)` to boot the VM.
   - Store the returned VM ID.

3. Implement `Container.ForceRemove`:
   - Call `client.Close(timeout)` then `client.Remove()`.
   - Handle the case where the VM was never launched (no-op).

4. Implement `Runtime.Close`:
   - No-op (the SDK client is per-container, not per-runtime).

5. Write unit tests.

## Files to modify

- `internal/matchlock/runtime.go`
- `internal/matchlock/container.go`

## Acceptance

A `Container` can be created, started (launched), and removed. Unit tests
verify the lifecycle methods call the expected SDK methods in the correct order.
