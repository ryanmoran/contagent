# P1-6: Wire matchlock runtime into config and main.go

**Status:** open
**Depends on:** P1-2, P1-3, P1-4, P1-5

## What to do

1. Update `internal/config.go`:
   - Add `"matchlock"` to `resolveRuntime`. Do not make it the default — it must
     be explicitly selected via `--runtime matchlock` or config file.
   - In `buildVolumes`: matchlock gets no default volume mounts (no docker
     socket, no SSH agent socket). Follow the apple runtime pattern.
   - In `buildEnvironment`: matchlock should pass `TERM` and `COLORTERM` but
     NOT `SSH_AUTH_SOCK` and NOT `ANTHROPIC_API_KEY` as a plain env var (secret
     injection is Phase 4). For the walking skeleton, pass `ANTHROPIC_API_KEY`
     as a regular env var temporarily so the flow works end-to-end — add a
     `// TODO(phase4): replace with AddSecret` comment.

2. Update `main.go`:
   - Add a `case "matchlock":` to the runtime switch that creates a matchlock
     runtime.
   - Import `"github.com/ryanmoran/contagent/internal/matchlock"`.

3. Update tests in `internal/config_test.go` to cover the new runtime option.

## Files to modify

- `internal/config.go`
- `internal/config_test.go`
- `main.go`

## Acceptance

`contagent --runtime matchlock echo hello` reaches the matchlock runtime code
path. Config correctly omits docker-specific volumes and env vars for the
matchlock runtime. Existing docker and apple tests still pass.
