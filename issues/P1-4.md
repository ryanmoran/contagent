# P1-4: Implement InspectUser and stub CopyTo

**Status:** open
**Depends on:** P1-3

## Context

The matchlock runtime uses `MountHostDir` to mount the repo into the VM (see
`docs/matchlock-sdk-findings.md`, finding #1). There is no tar-copy step — the
mount handles it. `CopyTo` exists on the `runtime.Container` interface because
docker and apple need it, but for matchlock it is a **no-op**.

`InspectUser` is still called by `main.go` to feed UID/GID into the git archive
builder. Implement it the same way the apple runtime does: exec `id -u` and
`id -g` inside the running sandbox.

## What to do

1. Implement `Container.CopyTo` as a **no-op** that returns `nil`.
   The repo enters the matchlock VM via a host directory mount configured in
   `CreateContainer`, not via tar copy. Add a short comment explaining why.

2. Implement `Container.InspectUser`:
   - The sandbox must be running (started). If not started, start it first
     (same pattern as the apple runtime).
   - Use `client.Exec(ctx, "id -u", opts)` and `client.Exec(ctx, "id -g", opts)`
     to get UID and GID.
   - Parse the output strings and return `runtime.ImageUser{UID, GID}`.

3. Write unit tests.

## Files to modify

- `internal/matchlock/container.go`

## Acceptance

`CopyTo` returns nil without side effects. `InspectUser` returns parsed UID/GID
from exec output. Unit tests cover both methods.
